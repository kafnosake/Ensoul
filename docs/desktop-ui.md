# 桌面组件协议与交付边界

桌面快速路径使用 `ensoul.desktop-ui.v1`。采用树状声明式组件目录规范，轻量表达常用桌面小组件。

```json
{"protocol":"ensoul.desktop-ui.v1","root":{"component":"calendar","props":{"weekStartsOn":1}}}
```

目录第一版：calendar（日历）、clock（时钟）、note（便签）、text（文字）、column（1–6 个子组件）。配置不允许 CSS、HTML、源码、颜色、尺寸或外部资源。运行时负责黑色磨砂材质、四角裁切、响应式布局及本地交互；模型只选择组件和参数。纯函数解析器位于 `src/shared/desktop-ui.ts`，插件后端通过编译后的公开共享模块使用同一解析器，渲染端直接使用源码。更改该共享协议需要编译并重启。

用户明确输入“日历”“时钟”“便签”时直接套用标准配置，不调用模型。新组件的较长需求如果能识别为日历、时钟、便签，先放置可操作的标准组件，再用一次模型请求配置定制项。首次可用不依赖模型完成；标准组件已经放置不等于定制要求全部完成。不强制按时间取消；用户可以停止配置，插件卸载时取消请求。无自动重试、工具循环、源码生成、构建或重启。不支持的需求说明原因并保留已显示的标准组件，不回退到无限开发循环。未知类型仍需模型选择目录，现有功能组件修改期间保留原视图。

创建和编辑沿用同一 panelId；真实需求和配置结果保存在原会话中，不制造推理内容。定制输出经过目录校验后才替换视图；失败保留原组件或已经放置的标准组件。组件被修改、收回或插件卸载时，过期结果不能覆盖现状。已有任意源码 / 网页组件不会自动迁移；用户点击编辑，输入“日历”等明确请求可以替换为标准组件。

桌面卡面接入既有 FitBox，声明式组件用本地响应式网格。卡面 flex 子元素清除固定 100% 高度，并使用完整圆角裁切，避免底角被窗口截掉。

磨砂层读取当前 Windows 静态壁纸，按显示器填充布局取样，在组件范围内模糊，叠加半透明黑色底。壁纸最多缩到 1920 像素宽并缓存；只模糊组件及其 24px 邻域，不为每块组件创建整屏模糊图层。它不是原生 Acrylic，不会采样动态壁纸、图标或其他窗口；尚未覆盖 Windows 壁纸的居中、平铺、跨屏模式和各屏独立壁纸。无法读取壁纸时只使用透明黑底，不声称有原生模糊。[微软文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmenableblurbehindwindow)明确说明旧 DWM blur API 在 Windows 8 起不会产生模糊效果。

收回组件时，宿主保存原位置、尺寸和窗口标记。主窗口提供“撤销收回”，恢复同一面板和会话；它不是通用工作区撤销。该记录随工作区保存，撤销后清除。更改之前已经收回且没有位置记录的组件，无法精确恢复原位置。

本次按用户要求只编译，没有运行行为验证；实际圆角、视觉、原生输入、生成耗时和撤销流程尚未实测。
