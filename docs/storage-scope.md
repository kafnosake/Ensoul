# 数据归属与存储范围

2026-10-08。本文定义已实现的存储规则与旧数据迁移边界。

## 1. 默认规则

**持久数据默认写固定的应用数据根；只有进入下面白名单的数据才写工作区。**

工作区是当前项目的文件目录。切换工作区改变项目上下文，不改变用户身份、面板身份、个人配置和资料库。

应用数据根独立于当前工作区。当前已有的全局目录由 `src/main/paths.ts` 的 `userDataDir()` 提供（Windows 为 `%APPDATA%/ensoul`）。若部署方式明确采用便携数据根，该根也必须固定，不得根据 `workspaceRoot()` 推导。本文不新增便携目录切换能力。固定数据根可与某次选择的工作区位于同一目录，但两者的路径来源必须独立；后续切换工作区不改变数据根。

应用的安装 / 源码目录保存自带代码和资源；不能因为它恰好也是当前工作区，就把其中的 `.ensoul` 当作全局数据根。

## 2. 工作区白名单

| 允许保存的内容 | 判断条件与例子 |
|---|---|
| 项目本体与交付物 | 源码、文档、素材、数据集，以及用户明确要求生成到该项目中的文件。用户指定其他输出目录时尊重该目录。 |
| 需要随项目携带的规则、配置和扩展 | 项目专属的 `AGENTS.md`、技能、可共享配置；明确选择“仅此项目”安装的插件或 MCP 定义。内容必须适合随项目复制或共享，不能混入个人偏好和凭据。 |
| 项目工具要求的本地依赖、构建产物和可重建缓存 | 项目使用的工具自身约定放在项目内的 `node_modules`、项目 `.venv`、`dist` 等；或用户明确选择放在项目内的某一类可重建缓存。 |

新增工作区写入点必须说明属于哪一类、为什么需要跟着项目走。未能说明时，采用应用数据根；不能以“插件一直这样写”“与项目有关”作为理由。

ensoul 自己的索引和缓存默认放应用数据根，按项目隔离。下载的共享解释器与运行环境也默认全局；不能通过改目录名获得工作区例外。

## 3. 其余数据的默认归属

| 数据 | 默认保存方式 |
|---|---|
| 面板、布局、当前对话、归档历史、个人便签 | 应用数据根，按面板或资料身份分槽。项目文件中的文档和便签仍属于项目本体。 |
| 个人组件模板、角色卡、头像、提示词库、布局预设 | 应用数据根；用户明确发布给项目的副本属于交付物。 |
| 插件个人参数、账号配置、个人 MCP 登记、个人技能和扩展 | 应用数据根；项目专属的可共享配置可以作为显式覆盖。凭据使用已有凭据机制，不写项目配置或普通状态文件。 |
| ensoul 安装的共享运行环境与资源 | 应用数据根；项目工具自身创建的项目环境按白名单处理。 |
| 任务记录、运行日志、恢复记录、文件备份 | 应用数据根；记录项目归属和原始目标，按项目 / 任务隔离。用户明确导出的备份副本可以写指定项目目录。 |
| 项目索引、Git / 构建状态快照、其他 ensoul 缓存 | 应用数据根，按项目隔离；只有明确选择的可重建缓存类别可以写项目内。 |

“全局保存”指固定存储位置，不代表所有项目混用同一份状态。`workspace`、`panelId`、`taskId` 决定记录归谁，不能代替存储根的选择。

## 4. 容易混淆的边界

- 从项目对话产生的历史、便签、角色信息，仍默认属于用户或面板；只有明确交付给项目的文件才成为项目内容。
- 插件 / 技能装在工作区，只说明代码和项目定义的安装范围。插件的个人偏好、凭据、面板状态仍默认放应用数据根。
- 用户导出模板、历史或备份到工作区，产生的是副本或交付物，不改变原始数据的保存位置。
- 项目覆盖只覆盖明确属于该项目的配置项；不能把全局配置与项目配置的合并结果整份写回工作区。
- 切换工作区不能把旧任务、命令或恢复动作改指向新目录。记录须保留原项目归属；正在执行的资源仍遵守已有取消和生命周期约定。

## 5. 当前实现与迁移边界

`.ensoul` 是托管的逻辑命名空间：默认映射到应用数据根 `.ensoul/`；项目状态映射到应用数据根 `projects/<工作区哈希>/.ensoul/`，并保存原工作区映射。项目插件、技能以及 `storage.workspace` 声明的共享配置仍留在工作区。普通项目文件不走这一映射。

插件 `api.state` 默认全局，直接文件用 `api.dataPath(relative)`。模块声明 `storage.project` 后，相应状态、命令和索引按初始化工作区隔离；个人参数在全局 `.ensoul/state/plugin-params.json`，显式项目参数覆盖在项目 `.ensoul/plugin-overrides.json`。合并结果不会整份写回项目。插件安装默认个人全局，也可明确选择仅此工作区。

启动时处理当前及已有最近工作区，切换前先迁移目标工作区。旧 `.ensoul` 文件复制后逐文件校验并保留原件；不同内容的同名目标保留现有文件，将来源副本存入应用数据根 `.ensoul/migrations/<工作区哈希>/conflicts/`。旧 `.cmd.json` 归档到 `commands/`，不会自动重放。迁移清单与报告在同一目录，重启不会把已删除数据重新恢复。

个人模板、历史、面板临时输出、运行环境和插件文件均使用新入口。任务及回合日志保留原项目归属，迟到的任务结果写回原项目分区。项目状态相互隔离、个人数据跨工作区可见、失败切换保留原工作区均有隔离测试。

旧文件不会自动删除；冲突副本需要按内容选择，不能自动当作同一数据合并。失效符号链接保留原件并把目标信息归档到 `links/`；有效符号链接仍在报告中报错，避免盲目搬运外部目录。当前工作区迁移失败会阻止加载，最近其他工作区失败只记录报告。第三方插件直接拼接工作区路径仍需改用 `api.dataPath`；声明与安装范围不能代替该接口。
