# 本地语义搜索

本次解决的问题：ensoul 只有关键词检索时，无法通过含义查找工作区资料和多模态素材。预期行为是通过可关闭的扩展提供实际向量检索，并在设置中逐项控制范围。功能实现位于 `plugins/semantic-search/`，不改变窗口、面板身份或聊天存储；设置宿主通过通用 `placement: 'more'` 声明支持独立下载入口。

## 使用

先进入设置 → 更多 → EmbeddingGemma 2，点击「一键配置」。它自动查找或下载 Python，创建独立环境，按所选 CPU/CUDA 设备安装依赖，准备模型并验证可用性；已有环境和模型缓存会复用。整个流程在后台执行，显示进度、真实错误并支持取消。Python 路径、模型路径和下载代理收在「高级设置」，通常无需填写。

然后进入设置中的「语义搜索」（位于「MCP 服务」下方），开启总开关，再点「更新索引」。这个分区集中管理功能开关、索引目录、向量维度和运行设备。初始总开关关闭；关闭会取消进行中的任务并释放模型，功能选择和索引保留。插件本身可在插件管理中停用。

设置分区提供以下独立开关：文档、代码、当前工作区会话、跨工作区旧会话、图片、音频、视频、助手检索工具、相似度比较、分类、分组、自动更新索引。跨工作区旧会话默认关闭，其余功能初始选中，但只在总开关开启时执行。

自动更新每分钟检查一次，复用内容未变的向量。首次下载必须在「更多」中主动点「一键配置」，搜索和自动索引不触发下载。索引目录可用分号限定为当前工作区的子目录；`.` 表示整个工作区。`.gitignore`、运行时缓存、构建产物与常见密钥文件排除在扫描之外。链接指向工作区之外的文件跳过。

搜索面板支持文字描述，以及工作区内的图片、音频、视频文件路径，可组合输入。结果显示原文、来源、行号或文档页号；分数是检索排名依据，不是正确率。点击来源可以打开文件或激活仍在使用的会话。归档会话的原文可以检索，但不通过已关闭的面板编号直接打开。

## 功能边界

- 文档：纯文本、Markdown、结构化文本，以及 PDF、DOCX、PPTX、XLSX 的文本提取。扫描 PDF 不含 OCR；没有提取到正文时给出警告。旧版 DOC/PPT/XLS 等格式不做静默转换。
- 代码：按文字描述检索切片，原文附真实行号。已知函数、错误或路径时仍先精确搜索，语义命中是候选证据。
- 会话：读取当前拆分存储的面板正文，仅当 `workspace.json.workspace` 与当前工作区一致。缺少工作区归属的旧关闭/收纳会话只有单独开关启用后才进入索引。
- 图片、音频、视频：直接使用模型的原生编码器。图片统一为 RGB，GIF 和多页图片使用首帧；视频按视频编码器采样。当前结果定位到素材文件，不生成转录、视频时间轴或剪辑。长媒体受模型上下文与采样预算限制。
- 比较、分类、分组：通过助手工具调用，支持多模态内容；分类分数不当作概率。分组使用本地向量聚类，返回输入项编号。

## 运行与存储

默认模型是 `google/embeddinggemma-2`。也可以配置兼容的本地模型目录。向量维度支持 128、256、512、768；更换模型或维度后需要更新索引。文本、图片和视频共用按需配置的编码器；关闭不需要的图片/视频或音频功能会在下一次加载时省去相应编码器。精度使用 float32 或支持设备上的 bfloat16。

运行设备和向量维度通过下拉选择即时保存，重新进入、重挂插件或重启后保留原值。运行设备可选择 `auto`、`cpu`、`cuda`；选择 CUDA 后在「更多」点击一键配置会补齐 CUDA 版 PyTorch 并验证实际 GPU 运算。只更换运行设备不会作废已有向量索引。下载代理可选择 `system`、`direct` 或 HTTP 代理 URL。系统代理经 Electron 解析，Python 子进程使用同一代理；模型已经缓存后不需要联网执行检索。代理凭据不要写入可分享的配置。

- ensoul 用户数据目录的 `env/semantic-search/`：全局管理的专用 Python 环境、模型缓存和运行日志，所有工作区复用。在 Windows 上为 `%APPDATA%/ensoul/env/semantic-search/`；解释器自动登记到「Python 解释器管理」，不更改当前激活项、不修改系统 Python。旧工作区 `.ensoul/runtime/semantic-search/models/` 的缓存首次配置时复制复用，旧文件保留。插件源码不包含模型权重。
- ensoul 用户数据目录的 `env-config.json`：统一解释器清单与激活项；打开工作区时一次性合并旧 `.ensoul/state/env-config.json`，后续删除不会从旧配置重新出现。
- `.ensoul/semantic-search/index/`：向量二进制、来源元数据与当前版本指针。成功编码后才提交完整版本；取消或失败保留旧索引。
- `.ensoul/semantic-search/commands/`：面板独立请求文件，携带 `panelId` 与 `requestId`，消费后删除。
- `.ensoul/state/semantic-search.json`：工作区开关与配置、进度，以及 `panels[panelId]` 内的操作回执。模型跨工作区共用，索引按工作区保存；请求结果按面板隔离。

索引更新有单写者约束，同时操作会明确返回忙碌，不会把另一块面板的结果当成自己的。工具取消、总开关关闭、配置变更、插件卸载及工作区切换都会停止本实例的后台资源。清除索引只删除本扩展的缓存，不删除原资料。

## 助手入口与验收

工具为 `semantic_search`、`semantic_index_update`、`semantic_similarity`、`semantic_classify`、`semantic_cluster`。检索和分析工具都受总开关及助手工具开关控制；比较、分类、分组还有自己的开关。`/semantic` 打开面板，`/semantic 描述` 直接搜索。

`find-recipe` 的做法检索通过 `recipe_search` 接入：默认只查角色卡 `.ensoul/state/agents/*.json` 的 `learned[].name/how` 与 `work/` 文档；不索引整张角色卡的提示词或其他字段。经验作为文档进入索引，受文档检索开关控制；删除经验后，下一次成功更新移除其向量。传 `includeHistory:true` 才扩大到已启用的会话范围，仍遵守旧会话许可。默认返回最多 3 条、正文合计 3000 字符；这不是精确的 token 上限。结果标明来源类型和截断情况，必须按技能检查适用条件、边界与验收。模型或索引不可用时回退限定目录的 `search`，历史回退 `history_search/history_read`。做法不会自动写入角色卡或升格为技能。

检索与分析工具声明只读权限，索引更新声明写入权限，使员工面板的工具套件与 PTC SDK 能按权限发现它们。`dev/copy/art` 套件动态纳入插件工具；显式限制的面板仍只得到获准的工具。

验收要求：关闭后不再编码；各范围开关立即过滤结果；两个面板的请求与取消不串；增删改后索引准确更新；中断保留上次完整索引；来源可验证；缺环境、缺模型、损坏文档、索引损坏不能返回伪成功。

隔离验证入口：

```text
node --test scripts/test-semantic-runtime.js scripts/test-semantic-index.js scripts/test-semantic-plugin.js
node --test scripts/test-semantic-setup.js scripts/test-settings-dialog.js
node scripts/audit-plugins.js semantic-search
node scripts/check-types.js
npm run build:renderer
```

真实模型验证和上述协议/生命周期测试分开报告。插件入口重挂和渲染窗口 reload 后才算当前应用已生效；构建成功本身不代表已运行。
