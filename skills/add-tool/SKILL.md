# 给这个软件加一个工具

工具走的是标准 function calling：模型看到工具清单，自己决定调用，主进程执行后把结果回灌。
加一个工具只动 `src/main/agent.ts` 一个文件、三处地方。

## 一、声明：`toolsFor(level)`

```ts
spec('工具名', '这个工具干什么、什么时候该用。模型只看这段字，写清楚。',
  { 参数名: { type: 'string' } }, ['必填的参数名']),
```

三档权限要放对：

| 档 | 谁能用 | 能干什么 |
|---|---|---|
| `read` | 所有面板 | 看目录、读文件、搜内容、读日志 |
| `write` | 能改文件的面板 | 上面 + 写文件 |
| `full` | 只有工作区那个对话框 | 上面 + 跑命令、构建、起停进程 |

危险操作（动进程、跑命令、删东西）只能放 `full`。

## 二、实现：`runTool()` 的 switch

加一个 `case`，返回值就是模型看到的东西，纯文本。

- **失败不要 throw，把错误当文本返回。** 抛出去会打断整个 agent 循环，
  模型失去"看到错误 → 自己修"的机会，等于把一次可恢复的失败变成死局。
- 长输出自己截尾，用现成的 `tailOut()` —— 报错都在末尾，前面的都是噪声。
- 要读文件、写文件，一律走 `fsapi` 的 `readText` / `writeText`：它把路径夹在工作区里，
  自己用 `fs.readFileSync` 就绕过了这层保护。

## 三、显示名：`describeTool()`

加一句中文，界面上这次调用就显示成那一行（不加就显示英文工具名）。

## 四、收尾

1. `build_project` —— 编译过不去就别往下走
2. `restart_project` —— 不重启，界面上看不到新工具

## 容易踩的坑

- 忘改 `describeTool` 不会报错，只是界面难看。
- 工具名不要和插件注册的重名：重名时以核心的为准，插件那个会被忽略（不报错，最难查）。
- `spec` 的第四个参数是**必填参数名单**，写错了模型会漏传参数，然后在实现里拿到 undefined。
  所以在实现里对每个参数都要兜一下默认值。
