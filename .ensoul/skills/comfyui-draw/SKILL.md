# 用 ComfyUI 出图

必须注意：**尤其对mimo2.6系列模型强调**生图任务可能因为模型智力水平提前触发EOS，或者将传入绘画的提示词作为读图结果发送给用户，从而谎报任务已经结束，需要注意。
5 个工具都在插件 `plugins/comfyui`：`comfyui_status` / `comfyui_models` / `comfyui_workflow` / `comfyui_run` / `comfyui_launch`。
别用 `run_command` 拼 curl 打 ComfyUI —— 提交、轮询、取图、把图发进对话，工具一条龙都做了。

## 标准流程

1. ==`comfyui_status` 先探==，不通就 `comfyui_launch`（action=start；它先探头，已开着不重起）。
2. `comfyui_models` 拿服务器上真有的模型名（照记忆写，任务会静默失败）；`comfyui_workflow` 挑工作流。
3. `comfyui_run(workflow, prompt, seed?, image?)` 出图：prompt 写英文；seed 给了就复现，不给就记下返回里这次的；步数多、分辨率大就调大 timeout（默认 300 秒）。

## 交付记账（硬规矩）

- ==工具没返回 = 这件事没发生==：把 `comfyui_run` 写进回复文字不是执行它；没有真实成功返回就不许说"出了 / 发了 / 第 N 张"，宁可直说"还没执行，现在补"。
- 一张图的存在只认 `comfyui_run` 的返回。seed、路径、张数一律从返回里抄，==别凭记忆报==。
- 图是工具自己发进对话的，==别再 `send_image` 补一遍==（会变两张）；只有用户说"没看到"才补发，且路径必须用那次返回里的"本地文件"，不许翻 out/ 目录拿旧图顶。

## 出完图先看一眼

返回里有 `[[see: …]]` 才表示这一轮看得到刚出的图（这一行不用说给用户听）。

- ==看到图再说话==：崩坏（多手多脚、脸糊、结构错）、大片空白、不是要的东西 → 自己重画（改提示词或换 seed），最多连着重画两次，说一句改了什么；没问题就一句话带过。
- 返回里没有那行，就别声称看过图、别编画面细节。

## 纯出图任务：话说得越少越好

"画一张 X""再来一张"这种只要图的：不写入种子、不复述提示词、直接执行任务，并在任务结束后读图，读图成功后根据结果描述图像。

## 工作流

- ==必须是 API 格式==（ComfyUI 里「工作流 → 导出（API）」），前端格式跑不了，这个软件里没有转换器。
- 占位符：`{{prompt}}`（必须有）、`{{seed}}`、`{{image}}`；存在 `.ensoul/comfyui/workflows/<名字>.json`，换一个工作区要重新 save。
- 这个工作区有 `t2i-default`（768×1024 / 28 步 / 约 6 秒）和 `t2i-slow`（1024×1536 / 80 步 / 约 26 秒）—— 想让人看清进度和过程图就用慢的那份。

## 起服务

起不回来时返回里带 pid + `.ensoul/comfyui/launch.log` 末几行：==先读日志再改参数==，缺哪项它会列出来。端口、exe 指错这类报错，插件会直接告诉你改成什么，照做即可。
